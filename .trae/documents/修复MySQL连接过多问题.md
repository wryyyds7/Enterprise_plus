# 问题分析
当启动所有微服务时，出现了MySQL连接数过多的错误（"Too many connections"）。这是因为：
1. 系统中有多个微服务模块（至少15个）
2. 每个模块都配置了独立的数据库连接池
3. 所有模块都使用默认的连接池配置，没有限制最大连接数
4. 总连接数超过了MySQL的默认最大连接数限制

# 解决方案
为每个微服务模块配置合适的连接池参数，降低最大连接数，确保总连接数在MySQL允许范围内。

## 实施步骤
1. **在common模块中统一配置连接池参数**：
   - 修改 `common/src/main/resources/application.yml`，添加Hikari连接池配置
   - 设置合理的最大连接数（建议5-10个）
   - 配置其他连接池参数，如最小空闲连接数、连接超时时间等

2. **确保其他模块继承或使用统一配置**：
   - 检查其他模块的配置文件，确保它们使用common模块的连接池配置
   - 如有必要，为特定模块单独调整连接数

3. **配置示例**：
   ```yaml
   spring:
     datasource:
       hikari:
         maximum-pool-size: 5      # 最大连接数
         minimum-idle: 2           # 最小空闲连接数
         connection-timeout: 30000  # 连接超时时间
         idle-timeout: 600000      # 空闲连接超时时间
         max-lifetime: 1800000      # 连接最大生命周期
   ```

# 预期效果
- 每个模块的连接池最大连接数限制在5个
- 15个模块总共最多使用75个连接，远低于MySQL默认的151个连接限制
- 避免因连接数过多导致的数据库拒绝连接问题
- 提高系统的稳定性和资源利用率

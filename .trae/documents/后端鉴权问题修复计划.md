# 后端鉴权问题修复计划

## 问题分析

1. **模块认证差异**：除common、enterprise、login外，其他模块缺少统一的Security配置
2. **网关认证问题**：网关要求所有请求（除/in/\*\*）需认证，但部分模块未正确配置
3. **Enterprise 401问题**：直接调用正常，但通过前端页面[/admin/enterprises](http://127.0.0.1:5173/admin/enterprises)获取信息失败，报错为：获取企业列表失败: Request failed with status code 401。但是后端的网关及企业模块未看到经过信息，是否为网关设置错误？
4. **User模块/error问题**：未正确配置Security导致请求被拦截

## 修复方案

### 1. 统一各模块Security配置

为所有缺少SecurityConfig的模块添加统一配置：

* 配置`anyRequest().permitAll()`

* 禁用CSRF保护

* 使用无状态会话管理

### 2. 修复Gateway认证过滤器

* 确保JwtAuthenticationFilter正确验证token并传递给下游服务

* 调整白名单路径，确保必要的公共接口可访问

### 3. 优化UserInfoInterceptor

* 确保拦截器只处理需要认证的请求

* 调整白名单，包含更多公共接口路径

### 4. 修复Enterprise模块401问题

* 检查前端请求是否正确设置Authorization头，

* 确保网关正确路由到enterprise模块

### 5. 修复User模块/error问题

* 为user模块添加正确的SecurityConfig

* 确保请求被正确处理，不跳转到默认错误页面

## 实施步骤

1. 为activity、advertisement、event、forum等模块添加统一的SecurityConfig
2. 修改Gateway的JwtAuthenticationFilter，优化token验证逻辑
3. 调整UserInfoInterceptor的白名单配置
4. 检查前端对enterprise模块的请求配置
5. 为user模块添加SecurityConfig
6. 测试各模块的接口访问情况

## 预期效果

* 所有模块接口可正常访问，不再出现AccessDeniedException

* Enterprise模块在前端  和APIfox中均可正常访问

* User模块不再跳转到/error路径

* 统一的鉴权机制，确保系统安全性

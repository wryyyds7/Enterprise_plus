# 移除模块skip配置，让所有微服务可执行

## 任务目标

将所有模块从普通JAR改为可执行Spring Boot应用，确保它们都能加载common模块的自动配置。

## 实施步骤

### 1. 识别需要修改的模块

需要修改的模块包括：
- [x] event 模块
- [x] forum 模块
- [x] advertisement 模块
- [x] activity 模块

### 2. 修改策略

对于每个模块的pom.xml文件：

**修改前**：
```xml
<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
    <configuration>
        <skip>true</skip>
    </configuration>
</plugin>
```

**修改后**：
```xml
<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
</plugin>
```

### 3. 实施修改

#### 3.1 event模块
- **文件**：`event/pom.xml`
- **操作**：移除spring-boot-maven-plugin的skip配置

#### 3.2 forum模块  
- **文件**：`forum/pom.xml`
- **操作**：移除spring-boot-maven-plugin的skip配置

#### 3.3 advertisement模块
- **文件**：`advertisement/pom.xml`
- **操作**：移除spring-boot-maven-plugin的skip配置

#### 3.4 activity模块
- **文件**：`activity/pom.xml`
- **操作**：移除spring-boot-maven-plugin的skip配置

### 4. 验证修改

修改完成后，对每个模块执行：
```bash
mvn clean package -pl 模块名
```

验证生成的是可执行JAR文件（大小通常较大，包含所有依赖）。

## 预期效果

1. **所有模块都成为可执行Spring Boot应用**
2. **启动时都会加载common模块的自动配置**
3. **SecurityConfig的输出语句会在所有模块启动时显示**
4. **各微服务可以独立运行**

## 技术说明

- **可执行JAR**：包含完整Spring Boot容器和依赖，可直接运行
- **自动配置**：启动时会扫描classpath，加载common模块的spring.factories中声明的自动配置
- **独立运行**：每个模块都可以作为独立的微服务启动

## 后续建议

1. 为每个模块添加适当的application.yml配置文件
2. 确保每个模块的启动类配置正确
3. 考虑使用Docker容器化各微服务
4. 配置服务注册与发现（如Nacos）

通过此修改，所有模块将成为真正的微服务，能够独立启动并加载统一的配置，便于后续的分布式部署和管理。

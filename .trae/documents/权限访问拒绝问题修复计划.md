## 问题分析

通过分析代码和错误日志，我发现所有模块都出现权限访问拒绝问题的根本原因是：

1. **UserContext 为空**：`PermittionService.hasRole()` 方法依赖 `UserContext` 获取当前用户角色，但 `UserContext` 始终为空
2. **拦截器配置问题**：只有 `login` 模块配置了 `UserInfoInterceptor`，其他模块（如 `user`、`enterprise` 等）都没有配置
3. **权限检查机制**：`@PreAuthorize("@permittionService.hasRole('XXX')")` 注解依赖 `PermittionService` 正确工作，但由于 `UserContext` 为空，所有权限检查都失败

## 修复方案

### 1. 修复 UserInfoInterceptor 配置

**问题**：只有 `login` 模块配置了 `UserInfoInterceptor`，其他模块都没有配置

**解决方案**：
- 将 `UserInfoInterceptor` 的配置移到 `common` 模块，让所有模块自动继承
- 或者，确保每个业务模块都正确配置了 `UserInfoInterceptor`

**实施步骤**：
1. 在 `common` 模块中创建一个全局的 WebMvc 配置类
2. 配置 `UserInfoInterceptor` 拦截所有请求
3. 确保所有业务模块都依赖 `common` 模块

### 2. 修复 UserContext 设置逻辑

**问题**：`UserInfoInterceptor` 可能没有正确解析 JWT 并设置 `UserContext`

**解决方案**：
- 检查 `UserInfoInterceptor` 的实现，确保它能正确解析 JWT
- 确保它能从 JWT 中提取用户信息和角色，并设置到 `UserContext` 中

**实施步骤**：
1. 查看 `UserInfoInterceptor` 的完整实现
2. 修复 JWT 解析逻辑
3. 确保用户角色被正确设置到 `UserContext` 中

### 3. 修复 PermittionService 实现

**问题**：`PermittionService.hasRole()` 方法在 `UserContext` 为空时返回 `false`，导致所有权限检查失败

**解决方案**：
- 优化 `hasRole()` 方法，添加更健壮的错误处理
- 或者，提供一个默认角色，允许基本访问

**实施步骤**：
1. 优化 `hasRole()` 方法，添加日志记录
2. 确保在 `UserContext` 为空时能给出明确的错误信息
3. 考虑添加一个默认角色，允许基本访问

### 4. 检查并修复各个模块的安全配置

**问题**：每个模块可能需要自己的安全配置，或者需要正确导入 `common` 模块的配置

**解决方案**：
- 确保每个模块都正确导入了 `common` 模块的安全配置
- 或者，为每个模块添加自己的安全配置

**实施步骤**：
1. 检查每个业务模块的安全配置
2. 确保它们正确导入了 `common` 模块的配置
3. 修复任何冲突或缺失的配置

## 预期效果

修复后，各个模块的 API 将能够正常访问：
- 管理员用户可以访问所有管理员接口
- 普通用户可以访问普通用户接口
- 权限检查将根据用户的实际角色正确工作
- 不会出现所有接口都被拒绝访问的情况

## 实施优先级

1. 首先修复 `UserInfoInterceptor` 的配置，确保它在所有模块中都能工作
2. 然后修复 `UserContext` 的设置逻辑，确保用户角色能被正确提取和设置
3. 最后优化 `PermittionService` 的实现，添加更健壮的错误处理
